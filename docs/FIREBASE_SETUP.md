# Бесплатный Google-вход и облачный прогресс Ground

Приложение использует **Firebase Authentication + Cloud Firestore** и работает на тарифе **Spark**, без банковской карты и Cloud Functions. Сайт остаётся на GitHub Pages. Firebase Web App config проекта **ground-f787f** уже добавлен в `js/firebase-config.js`; Google Authentication и Firestore Production mode включены владельцем.

Spark имеет бесплатные квоты чтения, записи и хранения. При превышении квот синхронизация может временно перестать работать; приложение сохраняет попытки на устройстве для повтора. Чтобы исключить расходы, сохраняй тариф Spark без подключённого биллинга. Код не включает платные функции, не меняет тариф и не подключает карту. [Тарифы и квоты Firebase](https://firebase.google.com/pricing).

## Два действия в Firebase Console

1. Открой [Firestore → Rules](https://console.firebase.google.com/project/ground-f787f/firestore/rules), вставь **полное содержимое** [`firestore.rules`](../firestore.rules) вместо текущих правил и нажми **Publish**. Используй правила из текущей версии: они учитывают курсы 8–11 классов, поля достижений `achievements`, серверную дату учебной активности `lastActiveAt` и обновление старых профилей без обнуления балансов. Даже если правила уже публиковались раньше, замени их актуальным файлом, иначе сохранение новых уроков и миграция могут быть отклонены.
2. В [Authentication → Settings → Authorized domains](https://console.firebase.google.com/project/ground-f787f/authentication/settings) добавь **projects0002013-web.github.io**, без `https://` и `/Ground/`.

Теперь открой [Ground](https://projects0002013-web.github.io/Ground/), войди через Google в приветствии или профиле. Первый вход создаёт профиль, повторный сохраняет XP, гены и уроки. Консоль или Firebase CLI для повседневной работы не нужны. Для локального запуска при необходимости добавь `localhost` / `127.0.0.1` в Authorized domains.

Не добавляй общие `allow read, write: if true`: пересекающиеся разрешения Firestore складываются и отменят защиту.

Если предпочитаешь CLI, нужен Node.js 22+ и вход владельца проекта. Публикуются только правила, без функций и биллинга:

```sh
npm ci
npx firebase login
npx firebase deploy --project ground-f787f --only firestore:rules
```

## Что сохраняется

- `users/{uid}`: имя/email/аватар Google, имя в приложении, курс, интерфейс, XP, гены, уровень, streak, дни обучения, сохранённые достижения (`first-lesson`, `five-lessons`, `three-day-streak`, `challenge-passed`), серверная дата последней учебной синхронизации `lastActiveAt`, пройденные занятия и экзамены, доступные этапы, краткая история последних 50 попыток, версии курсов, ревизия, ID последней попытки и серверные даты `createdAt`/`updatedAt`.
- `users/{uid}/attempts/{attemptId}`: ответы и результат отдельной попытки с серверной датой записи. В приложении отображаются последние 50; журнал сохраняет предыдущие записи для защиты от повторной отправки. Удаление истории не реализовано, её объём учитывается в бесплатной квоте хранения.

Приложение считает ответы по существующему каталогу уроков в браузере. Транзакция Firestore читает профиль и журнал попытки, затем атомарно записывает оба документа. При одновременном завершении на двух устройствах конфликт приводит к повтору транзакции с актуальным профилем. Награда начисляется один раз; повтор той же попытки возвращает уже сохранённый результат.

## Что защищают правила и что они не проверяют

Правила дают доступ только к собственному UID. Новый профиль начинается с нулевых XP/генов и пустых прохождений. Нельзя напрямую записать произвольные XP, удалить прохождения или переписать существующую попытку. Для прогресса требуется новая запись попытки в той же транзакции; прирост XP и генов должен точно соответствовать награде конкретного занятия, предыдущий этап должен быть пройден, повтор уже пройденного этапа имеет нулевую награду. Проверяются типы, размер полей, порог 70% и согласованность статистики.

**Правильность ответов вычисляет браузер.** Технически подготовленный пользователь может подделать собственный результат и пройти этапы, соблюдая допустимые награды. Правила не доказывают, что ученик действительно отвечал самостоятельно. Это приложение для личного обучения, не защищённый экзамен или денежная экономика. Чужие профили остаются недоступными. Полноценная проверка ответов доверенным сервером потребовала бы отдельного сервера; текущая версия обходится без него.

Дни и streak считаются в `Asia/Qyzylorda` по дате завершения попытки. Интерфейс, гостевой режим, недельный календарь и облачный движок используют одинаковый расчёт, независимо от часового пояса телефона или ноутбука. Очередь без сети и перенос гостевых ответов сохраняют исходный `completedAt`, поэтому занятия разных дней не схлопываются в день загрузки. Приложение отклоняет некорректные даты и время более чем на пять минут в будущем. Исходная дата заявляется клиентом; серверным временем подтверждается запись (`lastActiveAt`/`updatedAt`), а не фактическое время прохождения без сети. Достижение за три дня сохраняется и после перерыва в серии. Интерфейс пересчитывает актуальную серию из дней. XP и гены появляются после успешной записи транзакции в облако.

## Без сети, гостевой режим и перенос

Гостевой `ground.v2` не смешивается с аккаунтами. Кэши, очередь попыток и изменения настроек имеют ключи с UID пользователя. Без сети успешная попытка может открыть следующий урок на текущем устройстве; после восстановления сети очередь отправляется по порядку. Незавершённый урок остаётся локальным и не переносится между устройствами.

Выход возвращает гостевой профиль и удаляет локальный кэш вышедшего аккаунта. Неотправленные попытки и настройки остаются под его UID до повторного входа. На общем устройстве для полного удаления локальных данных очисти данные сайта после синхронизации. Service Worker кэширует только статические материалы и посещённые PDF; чужие данные или ответы Firebase он не кэширует.

При первом входе каждого Google-аккаунта в этом браузере, если есть гостевые ответы, открывается предложение переноса. До нажатия «Перенести» облачный прогресс не меняется. «Позже» закрывает предложение; повторный запуск остаётся доступен в профиле. Ранее заработанные баллы аккаунта не обнуляются. Прочитанные разделы книги объединяются с облачными, а настройки аккаунта сохраняются.

«Перенести гостевые попытки» и импорт JSON заново проверяют сохранённые ответы в приложении и отправляют попытки в Firestore. Произвольные старые XP без истории ответов не копируются. Исходный гостевой профиль остаётся доступен; перенос ограничен историей последних 50 попыток и текущими версиями уроков. Несовместимые попытки пропускаются, ошибки очереди видны в профиле.

## Вход на телефоне

На GitHub Pages вход использует popup на телефонах и компьютерах. Если окно заблокировано, приложение предлагает разрешить его и повторить вход; автоматического перехода на другой домен нет. Встроенный браузер мессенджера лучше заменить обычным Chrome/Safari. Redirect применяется только при совпадении домена сайта с `authDomain` или в локальном demo-эмуляторе. Некоторые мобильные браузеры блокируют стороннее хранилище между GitHub Pages и `ground-f787f.firebaseapp.com`, что мешает redirect. При недоступности постоянного хранения входа приложение пробует хранение в сессии, затем в памяти и показывает ограничение: для этих режимов вход на следующих посещениях не гарантируется. Для таких браузеров можно бесплатно разместить интерфейс на Firebase Hosting и открывать **https://ground-f787f.firebaseapp.com** — на том же домене, что authDomain:

```sh
npx firebase deploy --project ground-f787f --only hosting
```

Это дополнительный вариант, а не обязательная установка. [Официальные требования Firebase к redirect](https://firebase.google.com/docs/auth/web/redirect-best-practices). Не меняй authDomain на GitHub Pages без размещения Firebase auth helper.

## Проверка после установки правил

1. Войди через Google: должны появиться имя/email и статус «Прогресс сохранён в облаке».
2. Пройди первый урок 8 класса: **30 XP / 5 генов**, следующий этап доступен. В 7 классе остаются ровно **13 кружков**, зачёт — 28/40.
3. Обнови страницу и войди тем же Google на другом устройстве — прогресс должен совпасть.
4. Повтори первый урок с обоих устройств: общая награда остаётся 30 XP / 5 генов.
5. Другой Google-аккаунт начинает с отдельным профилем; выход возвращает гостевые данные.
6. Заверши урок без сети, восстанови сеть и проверь, что очередь исчезла, награда начислена один раз.

## Разработка и проверки

Официальный SDK собран в `js/firebase-sdk.js` и сохранён в Git; на GitHub Pages npm не требуется. После изменения SDK запусти `npm run build:firebase`. Правила наград генерируются из каталога `js/database.js`: после изменения вопросов/наград запусти `npm run build:rules`, проверь правила и заново опубликуй их. Уроки 7 класса и версия прогресса 2 сохранены.

```sh
npm test
python3 tests/browser_cloud.py
python3 tests/browser_offline.py
python3 tests/browser_pages.py
python3 tests/browser_smoke.py
npm run test:firebase
```

Браузерные облачные тесты используют тестовый SDK-адаптер с конфликтами транзакций и настоящий браузерный движок оценивания. Unit-тесты транзакций используют адаптер в памяти. Они не заменяют официальный тест правил.

`test:firebase` использует официальный Auth/Firestore Emulator Suite с проектом **demo-ground**, без реальных аккаунтов и функций. Нужны Java 21+ и доступ к `storage.googleapis.com` для скачивания Firestore emulator. В текущей облачной среде эта загрузка заблокирована прокси (403 Domain forbidden), поэтому проверка правил на эмуляторе не выполнена. Правила подготовлены, но не опубликованы в вашем Firebase-проекте: здесь нет авторизации владельца через Firebase CLI.

## Обновление курсов 8–11 классов

После публикации текущего `firestore.rules` повторный вход переносит профиль на актуальные версии курсов. Старые отметки заменённых тем 8–11 классов удаляются; актуальные отметки 7 класса и других направлений сохраняются. XP, гены, streak, дни, история и настройки не обнуляются. Rules допускают только удаление отметок устаревших курсов и обновление служебных списков: миграция не может добавить XP, подменить существующий результат или удалить отметку актуального курса. После переноса новые уроки проходят обычные проверки порядка и однократного начисления наград. Старые неотправленные попытки несовместимой версии не открывают новые кружки.

Тест адаптера миграции запускается через `npm test`. Официальные тесты Rules и SDK запускаются через `npm run test:firebase`; в текущей облачной среде загрузка эмулятора недоступна, поэтому её проверку нужно повторить в среде с доступом к загрузке. Публикация Rules в реальный проект этой задачей не выполнялась.

## Какие данные представляют прогресс классов и настройки

`completed` содержит ключи `7:1`, `8:1`, …, `11:16`, `ent:1`, `olympiad:1` и `book:chemistry`. Поэтому школьные курсы, олимпиады, ЕНТ и книга сохраняются в одном приватном профиле без потери направлений при смене выбранного класса. `completedLessons`, `completedExams` и `completedRoadLessons` содержат производные списки; `courseVersions` защищает от переноса отметки на заменённую тему. Настройки представлены полями `nickname`, `selectedGrade`, `layout`, `onboarded`, `bookRead`, `bookPage`, `scanPage`. Отдельных несовместимых дубликатов `settings` или `classProgress` нет.

Старые профили получают новые поля достижений и даты один раз в транзакции, без сброса XP, генов, истории или настроек. Повторный вход обычно не выполняет запись, если профиль и данные Google не менялись. Незавершённый урок остаётся в локальном кэше конкретного аккаунта и устройства.

## Обновление GitHub Pages

Код, собранный SDK и статические материалы публикуются вместе из `main`. При существующей настройке Pages на `main` обновление запускается после отправки коммита; проверь результат в GitHub → Actions / Settings → Pages. Если Pages ещё не настроен: Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save. На опубликованном сайте npm не нужен. Для диагностики старой версии выполни полное обновление страницы: новая версия Service Worker обновляет только статические файлы и не сбрасывает прогресс.

Контрольная проверка владельцем после Publish Rules: вход Google на телефоне и компьютере, подтверждённый перенос гостевых попыток, тот же аккаунт на втором устройстве, выход и другой аккаунт, урок без сети с последующим восстановлением соединения. Тесты с подменённым SDK и статический тест `/Ground/` не являются подтверждением работы production Firebase. В этой задаче публичный endpoint Firebase также недоступен через сетевой прокси; настоящий Google OAuth и доступ к опубликованным правилам не проверены.
