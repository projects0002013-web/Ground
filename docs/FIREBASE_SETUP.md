# Google-вход и облачный прогресс Ground

Код уже настроен на проект **ground-f787f**. Google Authentication и Firestore Production mode включены владельцем проекта. Публичный Web App config находится в `js/firebase-config.js`; это идентификаторы веб-приложения, а не секретный ключ администратора. Analytics не подключён.

## Что нужно опубликовать

Для облачного профиля необходимы **правила и две Cloud Functions**. Установка только правил не создаст профиль: браузеру намеренно запрещено создавать документы с произвольными XP. До публикации функций вход может состояться, но приложение покажет ошибку синхронизации; попытки остаются в очереди устройства.

Cloud Functions 2nd gen требуют тариф **Blaze** и подключённый биллинг. Проверь тариф и расходы в Firebase Console; установи уведомление бюджета. Код ограничивает каждую функцию десятью экземплярами, но это не является лимитом расходов. Если Blaze не подходит, нужен отдельный доверенный сервер; выдавать браузеру право изменять XP ради обхода этого требования нельзя.

На компьютере с Node.js **22**, из корня репозитория:

```sh
npm ci
npm --prefix functions ci
npx firebase login
npx firebase deploy --project ground-f787f --only firestore:rules,functions
```

Команда использует `firebase.json`, собирает серверный каталог из существующих уроков и публикует `ensureProfile` / `recordAttempt` в **europe-west1**. Firebase CLI самостоятельно использует учётную запись владельца; секреты и service account JSON не нужно добавлять в приложение или GitHub. Не меняй регион только на одной стороне: он указан и в `functions/index.cjs`, и в `js/firebase-config.js`.

## Как установить Firestore Security Rules через Console

1. Открой [Firestore → Rules проекта ground-f787f](https://console.firebase.google.com/project/ground-f787f/firestore/rules).
2. Скопируй **полное содержимое** файла [`firestore.rules`](../firestore.rules), замени текущий текст редактора и нажми **Publish**.
3. Опубликуй функции командой выше. Либо после ручной установки правил выполни `npx firebase deploy --project ground-f787f --only functions`.

Не добавляй общие `allow read, write: if true` или разрешение записи всего профиля любому вошедшему пользователю. Пересекающиеся разрешения Firestore складываются: дополнительное разрешающее правило отменит защиту.

Правила разрешают вошедшему пользователю читать только `users/{собственный uid}` и его `attempts`. Из браузера можно менять только имя, выбранный курс, вид интерфейса и отметки открытых страниц конспекта с проверкой типов и серверного времени `updatedAt`. Создание/удаление профиля, XP, гены, уровень, streak, прохождения, журнал попыток, UID и даты создания защищены. Серверный Admin SDK имеет доверенный доступ и применяет свои проверки.

## Разрешённые домены Google-входа

Открой [Authentication → Settings → Authorized domains](https://console.firebase.google.com/project/ground-f787f/authentication/settings). Добавь **projects0002013-web.github.io** — только имя хоста, без `https://` и `/Ground/`. Если используется другой домен сайта, добавь его. Для локальной проверки добавь `localhost` и `127.0.0.1` при необходимости.

Статический сайт продолжает работать на [GitHub Pages](https://projects0002013-web.github.io/Ground/). Вход вызывается кнопкой «Войти через Google» в приветствии или профиле. Первое успешное подключение создаёт профиль; отдельная форма регистрации не нужна. Повторный вход обновляет Google-имя, email и аватар, сохраняя накопленные награды.

Сначала используется popup; при блокировке приложение вызывает redirect. Браузеры с ограничением стороннего хранилища могут блокировать redirect между GitHub Pages и `ground-f787f.firebaseapp.com`. Для надёжного redirect на таких телефонах используй Firebase Hosting с тем же authDomain: `npx firebase deploy --project ground-f787f --only hosting`, затем открывай **https://ground-f787f.firebaseapp.com**. [Официальные требования Firebase к redirect](https://firebase.google.com/docs/auth/web/redirect-best-practices). Не устанавливай GitHub Pages как authDomain без размещения Firebase auth helper.

## Схема и защита начислений

- `users/{uid}`: Google-идентичность, настройки, `xp`, `genes`, `level`, `streak`, `lastLessonDate`, `days`, `completed`, `completedLessons`, `completedRoadLessons` (доступные этапы), `completedExams`, краткая `activityHistory`, версии курсов, `revision`, `createdAt`/`updatedAt` с серверными timestamps.
- `users/{uid}/attempts/{attemptId}`: результат с ответами и серверным временем. Последние 50 попыток отображаются в приложении; серверный журнал сохраняет остальные попытки для идемпотентности.

`recordAttempt` получает идентификатор занятия и выбранные ответы. Сервер заново проверяет ответы по каталогу, порог 70%, предыдущий урок и версию курса. Он не принимает клиентские XP, гены, правильные ответы или чужой UID. Транзакция обновляет профиль и журнал вместе; повтор запроса с тем же ID возвращает прежний результат, а повторное прохождение с новым ID не начисляет награду. Два устройства не могут получить двойную награду за один урок.

Это защищает целостность наград, но не превращает открытую учебную игру в защищённый экзамен: ответы учебных вопросов доступны в статических материалах. Отметки чтения страниц конспекта подтверждает сам ученик. Платежей и магазина нет.

День для streak определяется сервером в `Asia/Qyzylorda`. Попытки без сети засчитываются в день **синхронизации**, не по изменяемым часам браузера. В профиле хранится streak на момент последней проверки; интерфейс рассчитывает актуальную серию из дней, поэтому после пропуска дня она исчезает.

## Работа без сети и переход между аккаунтами

Гостевой `ground.v2` сохраняется отдельно. Кэш вошедшего пользователя и очередь имеют ключи с его UID. Во время работы без сети успешная попытка может открыть следующий урок на этом устройстве; XP и гены появляются только после подтверждения сервера. При восстановлении сети очередь отправляется по порядку. Незавершённый урок остаётся локальным и не переносится на другое устройство.

Выход возвращает гостевой профиль и удаляет локальный кэш профиля вышедшего аккаунта. Неотправленные попытки и изменения настроек сохраняются под его UID до следующего входа в этот аккаунт. На общем устройстве для полного удаления этих локальных данных очисти данные сайта после синхронизации. Service Worker кэширует только статические учебные ресурсы; посещённые PDF доступны без сети. Непосещённый PDF сначала нужно открыть с интернетом.

«Перенести гостевые попытки» и импорт JSON отправляют сохранённые ответы на серверную проверку после явного действия пользователя. Произвольные старые XP или отметки прохождения без ответов не копируются. Исходный гостевой профиль остаётся доступен; перенос ограничен сохранённой историей последних 50 попыток и текущими версиями материалов. Несовместимые попытки пропускаются, ошибки очереди видны в профиле.

## Проверка после публикации

1. Открой сайт на телефоне, войди Google, проверь имя/email/аватар и статус «Прогресс сохранён в облаке».
2. Пройди первый урок 8 класса: должно быть **30 XP и 5 генов**, следующий этап открыт. В 7 классе по-прежнему ровно **13 кружков** с зачётом 28/40.
3. Обнови страницу; затем войди тем же Google на ноутбуке. Награды, курс, настройки и пройденный этап должны совпасть.
4. Повтори первый урок на обоих устройствах: общая награда остаётся 30 XP / 5 генов. Выйди и снова войди — прогресс сохраняется.
5. Войди другим Google-аккаунтом: его профиль начинается отдельно. Гостевые данные не должны автоматически попасть в аккаунт.
6. Отключи сеть во время урока, заверши его, восстанови сеть: очередь должна исчезнуть и награды появиться один раз.

## Разработка и автоматические проверки

Официальный клиентский SDK собран локально в `js/firebase-sdk.js`, поэтому GitHub Pages не требует npm или внешнего CDN при открытии приложения. После изменения SDK entry/dependencies запусти `npm run build:firebase`; после изменения вопросов/наград — `npm run build:catalog` и заново опубликуй функции. Каталог и SDK сохранены в Git.

```sh
npm test
python3 tests/browser_cloud.py
python3 tests/browser_smoke.py
npm run test:firebase
```

Последняя команда использует официальный Auth/Firestore/Functions Emulator Suite с проектом **demo-ground**, а не реальные пользовательские данные. Нужны Java 21+ и доступ к `storage.googleapis.com` для загрузки Firestore emulator. `tests/callable.test.cjs` использует адаптер транзакций в памяти, `browser_cloud.py` — тестовый SDK-адаптер и настоящий движок проверки ответов. Они не заменяют проверку правил на настоящем эмуляторе.

В текущей облачной среде загрузка Firestore emulator была заблокирована сетевым прокси (403 Domain forbidden); полный тест правил не выполнен. Публикация правил/функций и проверка реального Google OAuth также не выполнены: Firebase CLI здесь не авторизован. Код и правила подготовлены для публикации владельцем проекта по командам выше.
